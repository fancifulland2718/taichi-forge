# 按包定义导出 AOT（实验原型）

[English](package_aot.en.md) · [独立 AOT SDK](aot_sdk.zh.md)

`ti.aot.export_package(module, directory, arch="cuda")` 尝试从普通 Python 包的计算定义生成
数值 TCM、可读 Host Python 和入口清单。应用继续使用已有的 `@ti.kernel`、
`@ti.func`、`@ti.real_func`、`@ti.pyfunc`、`@ti.dataclass` 和 `@ti.data_oriented`，无需增加导出装饰器、逐 Kernel 注册或组件根。
这个接口目前是小范围原型，不是完整引擎的一键发行接口，格式和支持范围尚未稳定。

## 生产与消费

可先调用 `ti.aot.check_package(module, arch="cuda", source_root="path/to/src")`。
它复用正式导出的声明预检，解析全部选定模块、owner/继承、准备闭包和类型化输入，
不构造应用模型、不编译数值 Kernel、不写输出文件；正常 import/init 仍会发生。
返回可 JSON 序列化的来源 hash、装饰器定义与类型清单、模板/owner 要求、目标分支、
输入和闭包来源。失败沿用 `PackageExportError`，不省略失败定义。
`declaration_check="passed"` 只证明声明阶段通过，报告明确将编译、Host 投影和消费
标为 `not_run`；不能据此宣称整个引擎已可导出。逐模块验证后，最终仍需完整导出与消费。

生产端对导入的源码包调用一次导出接口，并显式选择后端：

```python
import taichi_forge as ti
import my_engine

ti.aot.export_package(my_engine, "dist/my_engine_cuda", arch="cuda")
```

`arch` 接受 `cpu`/`x64`、`cuda`、`vulkan` 或对应 Forge 枚举。尚未初始化时按指定
后端启动，禁用静默回退；已有 JIT Runtime 时必须与其后端一致，不重置活跃的 JIT。
省略 `arch` 则使用已经选择的后端。

可传入 `caps=[...]`，直接复用 `ti.aot.Module` 的部署设备能力声明和原生加载检查。
例如需要 64 位整数的 Vulkan 包使用 `caps=["spirv_has_int64"]`。能力不会从 Producer
的 JIT 设备自动继承；省略时仍是原 Module 的基线目标。包清单记录请求值，TCM 的
原生目标合同保持权威，不通过更换后端或截断数据类型绕过不支持的能力。

输出目录必须不存在。导出扫描选定包目录中的所有 `.py` 定义，包含没有被包入口
导入的模块和未在测试中调用的 Kernel；也可传入单个源码模块。它不运行构造函数、
初始化 Kernel、Host 分支或 step 来收集编译覆盖。Python 模块仍需正常导入，顶层
导入副作用照常发生，因此生产输入应为可安全导入的定义包。

数值编译前会汇总已识别 Kernel 的独立输入签名问题，并与声明预检查错误一起报告。
错误包含模块、源码行、入口与参数名；不通过构造模型或执行测试猜测 `ti.template()`
类型域，也不省略失败入口。缺少类型来源的模板参数、缺少元素类型/秩的数组仍需补齐
定义合同；该诊断不意味着它们已受支持，也不限制原有 JIT 按实际参数运行。

对于同一应用源码目录下的多个顶层包，可加 `source_root="path/to/src"`。
接口复用既有静态导入审计：所选包仍扫描全部定义，并收集目录内的静态导入、
字面量 `importlib.import_module` 依赖、真实包初始化文件及 namespace 父路径。
输出必须在该源码目录之外；同名模块的实际导入位置须与扫描路径一致。
Forge/Taichi 兼容层和 Runtime 始终作为外部依赖，不重复编成应用载荷。

一个引擎有多个独立公开包时，可把它们同时交给原接口：

```python
import solver_api
import renderer_api

roots = (solver_api, renderer_api)
report = ti.aot.check_package(roots, arch="cuda", source_root="path/to/src")
ti.aot.export_package(roots, "dist/engine_cuda", arch="cuda", source_root="path/to/src")
```

多根输入要求共同的 `source_root`。每个选定包仍包含未被入口导入的源码子模块；
依赖闭包在同一次预检和 Module 构建中合并，相同来源只分析、导出一次，共用原代码
复用规则及资源合同。它不是逐包导出后拼接归档，也不要求建立求解器+渲染器组合根。
重复根去重，同名不同来源拒绝；任何根中的不支持定义都会使预检/导出失败。
清单/预检的 `module_roots` 记录显式选择，`sources`/`modules` 记录实际闭包。
`source_root` 中未被选定根覆盖、也未作为依赖到达的模块不自动纳入；构建方仍需
核对整个引擎的公开根和声明清单。当前一次导出使用一个代码模块，多物理代码分区
及其加载成本不由这个接口自动解决。

多根包沿用现有 `application_modules` 消费边界，不需要另一个 Runtime Linker。
正常混合 import 可从不同原命名空间取得对象并共享同一加载包；独立消费时
`library.host` 是第一个根，其他根可用 `library.module("renderer_api")` 访问。
源根选择只决定定义覆盖，不能替代实际编译、数值消费及实例隔离检查。

构造函数也可无条件调用 `ti.experimental.ResourceScope(self)`（或已证明的转发工厂）
来初始化声明状态，而不保存返回句柄。导出器仍验证 owner、初始化策略及 builder，
不把条件调用、其他 owner 或任意隐藏分配当作有效声明；这种空作用域不增加设备代码。

版本 66 支持构造器中的无条件局部赋值
`scope = ResourceScope(parent).child('child', self)`，也接受已证明的同义工厂。
父对象必须是未改写的构造参数，名称为字面量；子对象继续拥有独立分配作用域，
父对象的正常声明须以 `parent_scope.child = Child(...)` 指定该子类型。
消费者保留注册并拒绝替换已有子对象，不复制父对象状态。CPU/CUDA 局部检查覆盖
动态尺寸、两实例及无源码消费。此切片不支持隐式推断普通父属性赋值，也不扩展
`child.parent_dim`、条件注册或跨构造器组分配。

版本 67 按实际 MRO 先解析无条件 `super().__init__`，再分析派生构造的资源依赖，
允许派生组的 `owner_dim` 引用父构造的 `owner_reference`。多个构造器分配 Field 时，
每个构造器须有独立的显式资源组；未分组的跨构造器分配、组身份冲突及资源替换仍拒绝。
CPU/CUDA 局部检查覆盖与普通 JIT 对照、新尺寸、无源码消费、组/实例隔离和构造失败释放。
版本 68 进一步识别把参数转发到后续基类的 cooperative 构造：该 mixin 不单独生成
owner/数值入口；实际派生类提供完整 MRO 和资源合同，Host 构造仍只保存一次。
已有字段分配/绑定接口按实际接收对象选择合同，实例资源保持隔离。CPU/CUDA 局部检查
覆盖无源码消费及相同数值入口的复用；缺少实际接收类或资源投影不相容会明确拒绝。
固定布尔类布局可沿用 `ResourceScope.constant`：根据实际接收类解析常量，只把选中分支
的分配纳入该类合同，Host 原条件保留。不同接收类的分配调用复用现有合同选择，未使用的
维度不提前求值；CPU/CUDA 局部检查覆盖不同组布局、无源码消费及常量改写拒绝。
真实布局/ABI 差异仍可产生必要代码差异；同布局接收类复用已验证的共同入口。
不根据实例 `hasattr` 猜测字段缺失，也不把这种布局事实展开为任意模型布尔配置。

版本 69 支持同一父属性在互斥的已声明布尔分支中构造不同子类型，例如
`if self.method: scope.worker = First(self)` / `else: scope.worker = Second(self)`。
子类型可有不同字段布局和设备方法；父类和 Host 构造仍各保留一个定义。
只有实际读取子对象或对应选择值的数值入口才增加必要实现，无关入口和未使用的
兄弟对象配置不产生代码副本。选择沿用原静态依赖与入口绑定机制，编译用资源见证
在入口之间复用，不改变消费实例的独立状态。共有的外层存在条件可保留，初始 `None`
可以登记首个子对象；已存在的对象不能被登记操作替换。
CPU/CUDA 局部检查覆盖普通 JIT 对照、不同布局、7/19 尺寸、独立进程禁用私有源码消费，
以及错误类型和改写选择的拒绝；CPU 另覆盖未使用兄弟配置、可选分支和嵌套限定路径。
分支必须互斥且在共有存在条件内覆盖声明域。跨候选类型推断另一构造器输入、
`field_like` 来源或自由函数接收类型尚未补齐；导出不以首个子类型冒充这些合同。
闭包工厂与子实现选择的组合也未资格，不据此宣称完整刚体或全引擎导出已通过。

`source_root` 模式使用第 2 版包清单，消费者仍兼容第 1 版；旧消费者拒绝新版本。
`library.host` 仍是最初选择的模块/包。包内绝对、相对和 importlib 导入解析到
各自加载包的命名空间；任意表达式计算的动态依赖不被猜测为完整闭包。
清单记录这些站点，若它们请求未导出的本地模块，消费端明确拒绝，不回退私有源码。
外部普通 Python 依赖继续正常导入。原生/扩展模块及任意动态加载器并未因此获得通用投影。

| 产物 | 内容 |
| --- | --- |
| `code.tcm` | 原数值定义经既有编译器生成的目标代码及实际 ABI 合同 |
| `host/*.py` | 原构造、管理、调度方法；Kernel 方法替换为通用 Runtime 调用描述符，设备 helper 的源码移除 |
| `package.json` | 定义到代码入口的映射、实际捕获参数、来源与载荷 hash |

这是按方法拆分，同一个文件/类可以同时包含保留的 Host 方法和移走的数值方法。
不会把整个源文件编译成应用 `.pyd`，也不在 Host 中保存可重建数值函数的 AST。
已有 Forge Runtime 仍是外部依赖，不复制进这些产物。

独立消费方式只需要匹配的 Runtime Python 实现与原生运行库：

```python
from taichi_forge_runtime.aot import Runtime, load_package

with Runtime("cuda") as runtime:
    with load_package(runtime, "dist/my_engine_cuda") as library:
        model = library.host.Model(19, 2.0)
        model.step(True, 0.25)
```

`Model` 的实例构造和 Host 控制流在消费端正常执行。每份加载代码有独立的 Python
包命名空间，延迟导入的子模块绑定自己的代码 owner；每个实例持有自己的资源。
调用复用已有 Runtime 的参数快照/租约，不通过切换模块共享资源指针选实例。

普通 package 调用（包括混合模式）在相同绑定首次复用时，默认对适用的 CPU/CUDA
bitcode 或 Vulkan 1.3 SPIR-V 执行消费时特化并保留原生准备。首次调用仍使用通用 AOT；
模型维度从原合同自动选择，普通整数参数、数组内容和实例地址不固定为代码常量。
新实例可以共享代码，但各自保存参数快照。Host 数组仍按原路径传输；不复用陈旧数据。
device-range 任务和非适用代码格式保持通用 AOT，不吞掉特化编译错误或回退私有源码。
跨进程特化缓存与避免首次通用代码物化仍未实现，首次与第二次调用成本须分别记录。
当前资源寿命到 `LoadedPackage.close()`，尚未提供独立对象退休政策。

调用方也可以保留 Forge 前端，用自己的 JIT Kernel 创建、填充和处理输入输出；
AOT 边界是包内的数值解算代码，并不要求所有应用 Field 或脚本都导出。
已有 JIT Program 时使用 `ti.aot.borrow_runtime()`，通过 `runtime.import_ndarray()`
或 `runtime.import_dense_view(ti.experimental.ndarray_view(field))` 显式借入设备资源。
显式类型/rank 的数组入口使用既有运行时步长 ABI；CPU/CUDA 局部检查覆盖同一代码
消费新尺寸的连续 ndarray 和交错 Dense Field、调用方 JIT 前后处理、类型拒绝与
源树销毁后的调用退休。此路径不要求调用方分配函数进入包的源码闭包，不额外复制
借用数据；仍须满足设备、元素类型、秩、布局和生命周期合同，并安排 JIT/AOT 间的
执行顺序。私有解算源码保持不可用，不能回退 JIT 解算。
持久绑定输入也可沿用 `ResourceScope.borrow`，显式给出求解器需要的类型和形状：

```python
scope.borrow("values", values, external=True, dtype=ti.f32, shape=scope.dim("n"))
```

格式 59 将这种声明投影为包的数组输入/输出口。普通 JIT 保留原 Field，消费端接收
显式导入的设备数组/Field 视图；支持构造或普通准备方法绑定，不要求原分配类或源码。
当前覆盖标量和固定向量/矩阵元素，形状使用原维度代数。CPU/CUDA 局部检查覆盖标量/
向量读写、新尺寸、交错布局、重绑定后的旧 Graph 快照、类型/形状拒绝和源树退休。
准备时失败不替换旧绑定，调用时也检查实际资源合同；包关闭不取得调用方存储的销毁权。
格式 63 将类型化端口的 `optional=True` 存在性作为准备时绑定的 i32 参数。
`ti.static(self.values is not None)` 等显式检查进入同一份数值代码，不再按端口有无
展开数值版本。普通 JIT 保留原对象判断；准备时允许 `None`，清除当前绑定后旧
prepared 调用仍保留原资源和存在性快照。构造后尚未准备的可选数组/记录从未绑定状态开始，
正常 Host 的 `None` 可直接消费；绕过声明把它改为非空仍在准入时拒绝。
编译器记录资源访问受哪些存在性分支控制，消费端在提交前检查所选路径的必需输入；
无条件读取仍要求非空。内联 `ti.func` 与 `ti.real_func` 使用同一规则，未证明的设备
分支按“可能访问”保守处理，不放宽缺失资源准入。缺失且不被访问的数组使用按类型
缓存的空描述符；有秩数组仅保留原 Runtime 的一个物理字节 token，秩零标量保留一个
元素的有效描述符，不分配模型大小的占位资源。CPU/CUDA 局部检查覆盖双端口四种组合、
跨输入依赖拒绝、只查询存在性、新尺寸、嵌套 owner、向量/秩零输入和旧 Graph 快照。
可选普通记录的成员也可使用类型化端口，沿用 `parent_dim` 和 `require_le` 检查实际
消费尺寸关系；记录保留为 Host 数据，不要求调用方的分配类进入包。CUDA 局部验证
包含记录存在/缺失、新尺寸、尺寸关系拒绝及旧 Graph 的输入快照。
这些声明可以放在普通 helper 中；固定的 Forge 标量/向量/矩阵类型引用会在定义分析时
解析，helper 不被执行，调用方也无需增加导出专用包装。只包含记录输入的准备方法同样保留。
格式 64 将仅包含类型化外部数组、标量和维度的可选输入记录纳入同一动态存在性机制。
成员读取的分支依赖和尺寸约束在真实绑定时检查；记录缺失且该路径不可达时，不读取
缺失成员。CPU/CUDA 局部检查覆盖记录内动态循环、标量、`ti.real_func`、跨记录必需
依赖拒绝、准备后切换以及禁止导入前端/私有定义的独立消费。记录判断使用 `is None` /
`is not None`，不把可能重载的相等比较替换成存在性判断。
格式 65 进一步覆盖由记录控制的完整独立 Dense 工作区组，仍用原 SNode 配方分配，
检查所属实例和实际尺寸。记录缺失时不分配工作区，只有不可达的参数使用空描述符。
成功显式绑定 None 会移除该组当前绑定；提前返回不改变原状态，准备失败恢复字段和组，
原 Graph 继续持有快照。CPU/CUDA 无源码检查覆盖这些行为及尺寸不一致、外来工作区拒绝。
部分组的布局选择、记录内静态选项、或尺寸流向记录外资源声明仍保留原合同。
数值代码应检查记录存在性，不将工作区对象比较当成记录状态。任意条件输入、结构体元素及模型决定的元素形状
尚未接入这种端口。下文
`source_scope=True` 的借用仍是保留原分配组的另一种合同；旧 Component 的只读外部
Field 合同也未因此扩大为任意可写输入。

格式 61 将保留的 `ti.algorithms.sort`、`SortWorkspace` 和
`primitive_sequence().sort(...)` / `GraphBuilder.append_native` 接到现有原生 Plan/provider。
支持稳定升序、精确排序、NaN 最后及当前后端的原生方法；其他排序策略明确拒绝。
排序实现不复制进应用 TCM；直接调用按工作区复用准备结果，Graph 在 `bind` 时准备，
录制和准备均不执行排序。CPU/CUDA 无前端消费检查覆盖新容量、重复键稳定性、两个实例、
工作区清理、Graph 顺序及资源退休。尚不代表其他原生算法都已获得包投影。

## 首批支持范围与验证

- 顶层 Kernel 和普通 `data_oriented` 类的实例 Kernel、它们调用的 `func` helper；支持普通导入别名。
- 显式标量、向量、矩阵和结构体值，以及固定元素类型/rank 的标量、张量和结构体 Ndarray；不支持梯度参数。
- 普通入口可接收类型/rank 匹配、可写且 C 连续的 Host 数组缓冲区（例如 NumPy 标量/张量数组）。复用原生上传与回读，调用返回时结果已写回；临时资源随后释放。设备 Ndarray 保持原调用路径，不额外复制。此 Host 便利路径有传输和同步成本，不用于替代稳态设备绑定；重叠/别名、只读、非连续和结构体 Host 缓冲区明确拒绝。Graph prepared binding 仍使用设备资源。
- 构造函数中直接分配的带类型 Ndarray，以及由标量常量或带 `int/float/bool`、Forge 标量类型注解的构造参数赋值的 `self` 属性。
- `types.vector/matrix/struct`、math 向量/矩阵别名及 `dataclass` 保留原逻辑类型。结构体存储复用 `Module.add_ndarray_layout` 和消费者原生布局查询，不建立另一套 packing 规则。Host 类型投影目前提供参数构造，不等于完整 Python Matrix/Struct 操作接口。
- LLVM 的 `real_func` 保留真实函数调用边界。嵌套函数通过类型化隐藏参数接收标量和数组捕获；显式参数的浅层递归已检查，递归函数带隐式捕获时明确拒绝。Vulkan 尚不支持 real function，在发布产物前拒绝。
- 带类型的数值 `pyfunc` 作为 AOT 入口供 Host 调用，在 Kernel 内继续使用正常函数 lowering；数值 Python 源码移除。未注解的公开参数拒绝，不根据先前调用推导发行签名。这只覆盖已声明数值域，不支持任意 Python 对象、副作用或按调用作用域改变的实现；显式作用域查询会拒绝。原 JIT/Python 装饰器行为不变。
- 单模块导出按原模块命名空间解析相对设备 helper 导入，编译依赖后从 Host 导入中移除这些 helper；此类导入不要求消费者保留私有父包。
- 包内绝对导入（含函数内延迟导入）映射到本次加载的独立命名空间。普通 `import`、别名及 `from ... import ...` 保留绑定方式；不修改全局原包名，也不回到私有源码。没有 `source_root` 时，嵌套包的无别名绝对导入尚不支持；通配符与 builtin `__import__` 仍有明确限制。包外依赖按上述源码边界处理。
- 构造函数直接调用 `field`、`Vector.field`、`Matrix.field` 的 AOS 分配保留为每个 owner 的完整原生 SNode 组。extent 支持正整数常量、构造参数及其无条件单次赋值的 owner 别名。普通 FieldsBuilder 仅编译结构并提供原生 schema；消费者由同一原生布局编译器实例化。导出不执行应用构造函数，也不把 Field 拆成分别分配的 Ndarray。条件/歧义 extent、offset、未证明的 order 选择、梯度及用户显式构建的树仍待接入。

同包入口的 Host recorder 可使用 `ti.graph.Arg`、`ArgKind`、
`GraphBuilder.dispatch`、顺序节点和 `append`。`compile()` 生成引用已导出符号的
既有 `ExecutionPlan`，不生成组合 TCM。`graph.bind(arguments)` 返回原生 prepared
call，可反复 `run()` 或 `submit()`；`graph.run(arguments)` / `graph.submit(arguments)`
是每次重新 prepare 的单次便利调用，后者返回已有 Runtime ticket 并持有在途资源租约，
不推荐作为稳态路径。绑定方法保留 owner 捕获；prepare 对每个实例的标量/张量值及原生
资源取快照。正常 Host 也可复用 `graph.submit(graph.bind(...))`，后续提交同一已绑定对象
不重新准备；跨 Graph 的绑定明确拒绝。晚期准备中声明但尚不存在的 Plan 参数记录缺席状态，
不阻断无关入口；参数后来出现或改变时，旧 Graph 重新绑定仍要求重新构图。
后续 Host 修改不改变旧调用。`template_args={'self': owner}` 必须与
绑定接收者一致。`private_scalar` 复用已有 Plan 的不可变标量资源，支持顺序节点的独立
名称作用域。`private_ndarray` 描述每次原生准备独立拥有的标量元素存储。CPU/CUDA 的
平坦 `while_loop` 区域复用现有精确原生 Plan 执行器，支持提前退出和零次上限；CUDA
准备检查实际 conditional graph 能力，不静默加入 masked 或 Host 控制回退。控制参数
和区域须来自同一录制；predicate/counter 接受零维或一维 i32 数组。局部 CPU/CUDA
无源码检查覆盖两种控制形状、ticket 提交、私有数组隔离及 prepared 快照
交错执行。嵌套/Vulkan 控制配方和原生 provider 节点尚未接入此接口。循环上限目前在
录图时确定；改变上限须重新运行 Host 构图。

消费端 Host 的 `ti.graph.structured_control_capabilities()` 从当前加载的 Runtime
查询平坦 Kernel 循环路径：CPU 为精确 Host 循环，CUDA 在原生 conditional graph
可用时报告设备控制。查询与实际 prepare 共用原生能力判定，不编译、录图或分配数组；
普通构造代码可据此选择控制资源，重放不隐式重复查询。`GraphBuilder` 保留类方法可见性，
支持检查 `private_ndarray`。这不是任意嵌套/provider 图的资格承诺，具体图仍在 prepare 验证。

普通构造器可调用同类的资源分配方法；Forge 复用原资源声明和 context manager
分析，不执行构造器，不展开或删除消费端 Host 方法。当前方法只接收 `self`，须为单次、
直接调用（包括接收返回值），允许嵌套转发。调用可以位于已声明布尔 owner static 的
`if` 或条件表达式分支中；条件随资源合同传递，关闭分支不分配资源或读取其尺寸。
末尾可返回普通 Host 计划；提前返回、yield、未声明条件、循环调用、替换或继承覆盖仍拒绝。
分配之后的普通 Host 初始化及 context 的异常清理仍按原顺序执行。不同方法可以重复相同的
维度声明；冲突维度和重复资源分配仍拒绝，不推断隐式重分配合同。

同模块子类继承构造器时，可以增加普通构造 hook 和固定 Struct 成员方法。Forge 将相关
继承 Host 方法投影到具体类的上下文，保留实际布局及分配顺序。类型成员方法只能从普通
参数返回单个固定名字的内置类型字典；模型宽度继续使用原维度投影，发现时不运行构造器
或类型方法。副作用、实例方法替换、复制方法中的词法 super/私有类状态及未知工厂拒绝；
不覆盖任意跨模块构造 override。CPU/CUDA 局部无源码消费验证不同宽度、独立实例、零初始化
及不受布局影响的入口共享。GeoPhys 几何/row 声明检查保留原三/六组资源，完整刚体导出仍待完成。

版本 35 支持构造路径中单次赋值的局部 vector/matrix/Struct 类型别名，包括由已声明模型
尺寸决定的成员宽度。类型来自原内置工厂；消费端在 Field 分配前检查成员顺序、dtype 和
实际宽度，类型构造后的改写不能静默改变导出布局。Struct 的 `member_initialization`
支持固定成员名的字典或单层生成式及字面量成员过滤，保留 `zero/consumer_explicit`
策略；不执行模型数据驱动的字典生成或新增快照策略。原生组的初始清零满足 zero 要求，
普通 Host 的显式初始化保持原调用位置。

版本 33 的 `scope.value('iterations', ti.i32, affects_plan=True)` 将“数值运行参数”与
“Host 计划依赖”分开：数值代码仍读取普通 ABI 输入，不按次数生成特化；Graph 记录时
保存该参数，编译及重新 bind 检查它没有改变。改变后重新运行正常 Host 构图，再 prepare。
已准备调用保持旧快照。未标记的普通值仍可在 bind 时更新。该标记限标量，要求 Host
录图期间保持模型参数稳定；它不自动分析任意 Python 分支。旧 Component Graph 复用
现有配置准入保存选定值，Kernel 的静态身份不包含这个值。
- 数组尺寸、普通标量属性按运行时数据传递。内部复用 Component lowering 的类型合同，不要求用户注册 Component；extent 为 1 的临时数组只提供类型/维数见证，不选择模型或静态分支。
- 正常 JIT 装饰器与调用路径不变；包扫描和 Host 投影仅在显式导出时执行。

源码边界模式也已用于原 winding 模块。原采样依赖闭包现已在 CPU/Vulkan 导出并独立

extent 仍须合法；当前结构见证不能满足的表达式明确拒绝，不运行模型求样本。
原始 SNode/Sparse 布局、条件或重绑定 scope、动态属性名和 scope 逃逸仍未接入；
静态域及有限条件字段的当前支持见下文。不支持的声明在发布包前明确拒绝。

构造函数中可由所选后端证明的条件（`ti.cfg.arch` 或

也不阻止原 Graph recorder 引用已加载入口。其他未投影前端 API 继续拒绝。
三后端局部检查覆盖两实例交错 Graph、绑定快照、私有标量作用域、外来 owner 拒绝，
以及记录/重放前后代码资产不变。

不执行应用构造/数值计算发现声明。builder/placement 逃逸、原始 SNode 构建和动态 Sparse
仍拒绝。三后端局部检查逐节点对照 JIT 布局并独立无源码消费；本次 Vulkan AOT 目标拒绝
f64，因此 Vulkan 用 f32 验证相同布局路径，CPU/CUDA 保留 f64 检查。

### 普通资源声明工厂

构造器中无条件调用的普通 Python 工厂，若能证明只在固定前端能力条件下转发到
`ResourceScope`，可使用同一声明投影，无须新增装饰器。当前证明范围为显式参数、
不可变字面量、转发的局部名称、前端 `getattr/hasattr` 能力检查及 ResourceScope
签名检查；不执行应用工厂或构造器。副作用、模型数据条件、未知全局依赖、参数调用
表达式和被遮蔽的工厂名称均拒绝。清单 `declaration_factories` 记录来源及摘要。

独立的 `ResourceScope(self).value(...)` 或已证明的同义工厂调用可复用局部 scope 投影：
在该语句位置绑定句柄后保留原方法调用，不跨控制流移动，不从任意参数表达式中提取。
CPU/CUDA 检查覆盖复合捕获与独立进程消费。此支持不同时补齐应用模块内保留的、直接
构造 ResourceScope 的工厂函数体之 Host 投影。

已投影且不再使用的工厂导入从 Host 移除。其他 Host 调用和依赖不因此删除；这不等于
支持任意工厂、上下文管理器或整个工厂模块的闭包。GeoPhys 原 `resource_scope` 的
固定转发路径经过三后端定向检查。应用模型、合法静态域及其余 Host 依赖仍需各自资格。

### 按实际静态依赖导出

无条件的 `scope.static(name, choices=..., kernel_only=...)` 支持显式、有限、不可变字面量域，
使用清单版本 11。编译器先编译声明域中的一个合法取值，随后只沿该 Kernel 实际读取的
静态依赖探索其他取值；新分支读到的新依赖继续由原编译器收集。未读取的配置不生成数值
副本，不枚举整个 owner 的组合，也没有统一变体数量上限。不能编译的合法分支使整个导出失败。

多个逻辑方法可引用同一相容编译结果。消费端按实例当前的合法静态值选择已导出的代码；
Graph 在录制时选择代码，并沿现有绑定保存调用快照，不编译新的组合或切换模块共享指针。
局部三后端检查覆盖分支相关依赖、无关选项、同实现继承、两实例、无源码消费及原 JIT 对照。
相同检查也覆盖 CPU/CUDA 的 `real_func` 传递静态依赖；Vulkan 保留原 LLVM-only 拒绝边界。

### 条件 Dense 成员

清单版本 12 支持已有布尔 `scope.static` 控制的 `if self.flag` / `if not self.flag`

保留一份原生组拓扑及成员条件，消费端选择成员后仍由原生 SNode/StructCompiler 实例化，
不按所有开关组合保存多套布局，不计算另一套字节偏移，也不分配关闭分支的字段。

原编译器在实际访问条件字段时记录其存在性依赖，因此也支持 `ti.static(field is not None)`；
不读取该字段的公共方法继续共用数值代码。实例的布局选择冻结，新调用若改变该选择则拒绝，
须创建新实例；已经准备的
原生调用仍使用原快照。每个组及显式 Dense 放置须能证明在其启用时至少有一个成员；
条件资源上下文可以整组不分配。任意模型条件及分配空组仍待接入。

被遮蔽的 setattr、模型驱动的名字列表及额外循环体操作拒绝。不会执行模型循环，也不会

## 从定义推导模型张量元素尺寸

版本 34 支持资源声明之前读取的单次局部尺寸别名，包括 tuple/list 解包和已有整数
维度代数。导出只关联别名与后续声明的尺寸来源，不执行构造器；分配时核对原别名值与
当前声明尺寸，来源在中途变化会拒绝。重赋值、删除和越出声明分支的别名不能用于这一
推导。普通整数读取与 `scope.dim()` 的 Extent 对象分别处理：显式 Extent 仍受原命名空间
约束，`require_le` 仍要求声明的符号表达式。CPU/CUDA 局部检查覆盖动态二维 Field、
模型 vector 元素、新尺寸无源码消费及分配前失配拒绝，不表示完整 Newton 已导出。

版本 26 可从 `Vector.field` / `Matrix.field` 构造参数及已证明的单次赋值别名，
以及 ResourceScope 的已声明维度，自动推导模型元素轴。平坦 Struct Field 的 vector/matrix
成员采用相同规则，保留原 AOS/SOA 布局；固定 `3`、`2×2` 等数学维度仍是固定类型。
不运行模型构造、不枚举 DOF、不新增应用装饰器或手工 ABI。

已有 `record.static('dof_count', choices=(layout.dof_count,))` 只有在唯一取值来自该记录
同一成员、且定义中确实用于张量元素轴时，才投影为模型维度。字面量有限静态域不变；
其他计算域、错来源及无元素轴用途拒绝。原 JIT 声明继续使用正常类型特化。

编译代码通过零复制标量轴访问原 Field；Host 仍看到正常逻辑 `shape`、张量 `element_shape`
及 `n/m/ndim`。SNode 配方、固定兄弟成员和实际字节布局由原生编译器统一实例化，
不发布构造见证尺寸的 StructNdarray ABI。调用和 Graph 重新绑定验证元素尺寸关系；
模型尺寸改变须创建/准备新的状态，不能原地修改尺寸后继续使用旧分配。

局部检查覆盖 CPU/CUDA/Vulkan 的直接 Vector/Matrix 和 Struct Field、独立实例、
屏蔽前端后的新尺寸 129 消费；CPU/CUDA 另覆盖 `real_func`。GeoPhys 原
`declare_batch_layout` helper 也通过三后端无源码布局消费检查，未改写生产 helper。
这不等于完整 EFC：一般整张量运算、同组条件布局与模型张量的组合仍待接入。
固定元素 Ndarray 和显式值参数的类型合同保持原范围。

版本 27 另将模型尺寸的 `Vector.zero`、`Matrix.zero` 局部变量降低为调用私有的标量数组
工作区。长度须来自不可变的 i32 捕获值或声明维度表达式；可变局部别名、设备读回的长度
明确拒绝。已声明的外层 range/ndrange 为每个逻辑工作项分配独立片段，包含 inline helper；
每轮在原声明位置初始化，局部值拷贝使用独立片段。固定尺寸局部变量与普通 JIT 仍走原路径。

消费端使用本次调用已冻结的标量参数计算尺寸，复用 Runtime 分配和在途提交所有权；
不切换模块共享指针，void 调用不为释放临时存储显式等待。空范围只需最小合法描述符。
表达式和总索引须满足现有 i32 数组 ABI，未设有限模型尺寸域。目前存储随逻辑工作项数量
乘局部元素数量增长；本批不宣称性能收益。
普通提交在 Runtime 正常完成前保留临时存储，退休工作区复用仍可后续优化。
定义包 Graph 在 bind 时从同一参数快照确定尺寸，使用原 ExecutionPlan 私有数组资源；每次
prepare 独立拥有工作区，replay 复用它们，不再逐次分配。不同数值入口的局部名称分别绑定，
同一顺序 Graph 内重复使用同一入口可复用其片段；原生 prepared 所有权负责在途保留与释放。

CPU/CUDA/Vulkan 局部检查覆盖屏蔽前端的新 DOF 129、独立实例、拷贝、重复初始化及回收。
GeoPhys 原 exact EFC 装配的编译器层检查也通过 DOF 3/17/65 共用代码、原 JIT 和独立质量
响应对照；该测试显式提供模型声明投影，不是整类定义包资格。

CPU/CUDA 的 `real_func` 可通过隐式数组和工作项索引参数使用同一局部工作区机制，包含嵌套调用。
不同调用位置共享函数实现，按调用范围的最大需求准备存储；函数内部循环复用当前工作项的片段。
递归中的隐藏捕获继续拒绝，函数显式参数不自动推断为可分配尺寸。Vulkan 的 real_func 限制不变。
一般整张量代数及旧显式 Component Graph 的局部工作区尚未接入。

模型 Vector/Matrix Field 现支持整元素读取、回写及标量填充。`value = field[i]`
得到独立局部值；链式局部赋值各自拥有值，交换赋值先保存全部右侧值再回写。
Field 与局部构造器的尺寸沿已有声明关系核对，不因构造见证中长度碰巧相等而允许赋值；
不同元素类型、秩或未证明相同的尺寸拒绝。固定数学张量和普通 JIT 保持原行为。

整元素快照复用上述调用私有工作区与标量数组 ABI。即使数值体只从 Field 描述符读取长度，
实际用于准备工作区的维度也进入调用快照；不枚举尺寸或实例生成代码。CPU/CUDA/Vulkan
局部检查覆盖新尺寸 3/65、非均匀元素值、拷贝独立性、交换、无前端消费和独立 prepared
调用，CPU/CUDA 另覆盖 `real_func`。这不是一般动态张量代数或整类 EFC 导出资格。
普通调用复用未变化绑定的 workspace；设备内的值拷贝仍执行。整元素拷贝可能比逐元素
直接复制使用更多临时内存，不能用 Graph 内部执行时间代替 prepare 和正常 Host 调用成本。

模型尺寸的 `ti.simt.block.SharedArray` 在 CUDA 内联并行范围内使用原生线程组共享存储。
标量元素和多维尺寸来自不可变声明值；每个任务按调用参数快照计算对齐后的总字节，
代码首次加载时查询设备与函数实际共享内存容量，并扣除原生编译后的静态占用、一次配置
可用动态额度。没有额外的统一字节数或模型 DOF 上限，也不随实例修改函数属性。
原应用选择其他算法路径的条件仍由 Host 保留；不会自动换成全局数组。新 lowering 不修改
共享的 TensorType，避免旧大数组路径污染后续编译。普通调用先验证全部任务，Graph 在 prepare 时固定额度，
尺寸变化须重新绑定。原 `block.sync` 和共享原子操作保持线程组语义。

局部检查覆盖一份代码的不同新尺寸、二维模型尺寸、固定/动态数组混用、原子累加、独立
实例、无前端消费、Graph 重放和实际设备超额拒绝，支持设备上另检查超过 48 KiB 的实例。
CPU/Vulkan 动态 SharedArray、real_func 内部
声明及设备决定的尺寸未取得支持。LLVM AOT 任务格式统一更新为 **21**，编译缓存更新为
**101**；旧构建产物需要重建，不提供旧任务记录兼容层。固定 SharedArray 的普通 JIT
语义保持。这些检查不等于整个 EFC 或整引擎已完成导出。

### 模型尺寸相关的静态控制

版本 28 将已证明来自模型元素轴的 `ti.static` 整数算式、条件及
`range/ndrange/grouped(ndrange)` 迭代复用为运行时控制。普通 JIT、固定数学维度及
真正的静态配置保持原路径。导出不按 DOF 枚举代码；原静态迭代的顺序也保留，
顶层循环不会被改成并行循环。直接 Field 的 `self` 尺寸别名连接到同一维度关系。

显式声明的 `ResourceScope.dim` 尺寸现可使用同一 lowering，不要求该轴同时用于模型
张量 Field。静态局部别名以及 prepare 决定的 CUDA block/共享数组复用原合同；普通
runtime scalar 声明仍不能进入静态控制。局部 CPU/CUDA 检查覆盖上述区别、新尺寸和
无源码共享存储消费。

模型统一条件只包围一个普通 `range/ndrange` 或稠密数组循环、且没有 `else` 时，
Forge 可将条件放入循环范围：条件为假时零次迭代，为真时保留原并行任务及 block 设置。
这里处理普通并行循环，不改变原 `ti.static` 循环的顺序语义。只有无副作用的范围表达式
适用；设备索引、范围中的函数调用和稀疏迭代保留原控制流。CPU/CUDA 检查同时核对
后端任务类型和无源码调用结果；这项 lowering 本身不代表可选输入 ABI 已完成动态化。

设备数据或可变局部量不能因此进入 `ti.static`；需要 Python 对象选择、类型构造或
编译期索引的循环体不自动获得运行时等价实现。循环范围须有可验证的整数维度表达式；
普通调用及 Graph prepare 从实际参数快照核查现有 i32 循环 ABI 的中间运算，防止
溢出后少执行迭代。此检查不是 DOF 数量或性能额度，prepared replay 不重复检查。
旧显式 Component Graph 尚未接入这些快照检查，遇到此类循环明确拒绝；上述 Graph
证据限定义包路径。底层裸 Kernel 调用者仍须遵守导出的参数及范围合同。
有限生成式工厂输入见下节；未知调用域和模型条件布局仍待处理。模型控制 CUDA block 大小走下述 prepare 绑定路径，不能据此宣称整个 EFC
类可导出。CPU/CUDA/Vulkan 的局部无源码检查覆盖新尺寸、实例隔离、顺序语义和 Graph。

动态控制可能减少编译展开，同时增加运行时循环、寻址或分支成本。性能结果按实际
设备和调用路径记录；明显成本可警告，不因性能差距拒绝可执行模型。

## 原定义中的 Kernel 工厂

版本 25 支持普通构造函数中无条件绑定的直线型 Kernel 工厂：一个原嵌套 `@ti.kernel`，
随后直接返回该定义。输入须由正常声明证明为本 owner 的直接、无条件 Dense Field 或其元组，
以及不可变常量；类型前缀可使用原 `tuple`、`len`、整数运算和内置 vector/matrix 类型。
导出不调用工厂或应用构造函数。它复用原 Python 代码对象及既有数值编译器，Host 保留
原工厂的组织与类型准备代码，数值体替换为通用绑定调用，不携带私有数值 AST。

词法资源沿普通捕获参数及原生组布局传递；只读取的成员进入 ABI。相同定义和参数结构
复用代码，Host 绑定位置不制造副本。向量/矩阵/结构体值参数使用结构类型身份，不使用
Python 对象地址。实例闭包保留构造时的资源快照；替换 owner 属性不会重定向旧闭包，
原分配退休后拒绝调用。未知类型来源、工厂副作用、混合来源实例及不相容绑定明确拒绝。

CPU/CUDA/Vulkan 局部检查及原 GeoPhys 相机上传工厂的独立无源码消费者已通过。
GeoPhys 检查使用未改写的原工厂源码和最小资源声明，不代表完整相机/渲染包已导出。
版本 31 进一步接受原 `functools.lru_cache` / `cache` 和按已证明固定输入进行的条件返回。
工厂中的数值定义须有不同名字，并在所在分支立即返回；导出仍不执行工厂、缓存包装器或
模型构造。Host 保留原缓存和分支，缓存容量来自应用原定义，不限制模型规模或发行代码数。
任意包装器、动态缓存参数、设备/模型数据决定的未知工厂条件和副作用不进入此路径。

不同 Host 标签选中同一定义时共享实现；`opt_level` 作为实际编译选项进入导出身份及消费
匹配，不混同于词法捕获。包中未构建的选项拒绝消费。只在装饰器用到的选项不会误加为
Kernel 运行参数。此版本复用已有 Dense Field 来源与实例快照。局部 CPU/CUDA/Vulkan 无源码消费已验证，原 Newton
仅通过工厂定义发现，不能据此声明完整 Newton 可导出。

版本 32 支持工厂返回的 Kernel 以首个 `self: ti.template()` 接收已声明 owner，复用
已有 Component 模板捕获及 entry 实例绑定。消费者可显式传入 `self`、通过 `__get__`
绑定，或用原 `GraphBuilder.dispatch(..., template_args={'self': owner})` 记录。
缓存对象共享代码选择，不保存可变的“当前实例”指针；普通调用读取所传实例，prepare
固定各自参数/资源快照，重放不重新选择 owner。复用入口描述符，未在每次调用重建选择表。

此路径不同时混入词法 Field 所有者；额外模板参数、未知接收类、跨 package 实例及
退休资源拒绝。模型决定的工厂类型仍待补齐。局部三后端检查及原 GeoPhys `_cooperative_kernel` 工厂源码的
CPU/CUDA 无源码消费通过；后者使用最小数值宿主验证绑定，尚非完整 Newton 算法验收。

构造器中的有限工厂输入可由已有 `scope.static(..., choices=...)` 推导，无需新注册。
支持固定 tuple/list、`zip` 和单层生成式（含 `tuple(...)`），以及固定条件或有限声明
决定的可选 `None`。只展开到达每个工厂调用的输入：两个阶段的选项分别投影，不按
整个 owner 配置的笛卡尔积生成实现；真正被数值代码读取的静态条件仍保留必要特化。
同一阶段的不同编译选项分别保留入口选择表，不互相覆盖。

导出不执行这些 Host 表达式；消费者保留原 Python 顺序、可选阶段和缓存行为。只接受
可证明的单次赋值别名；重绑定、序列修改或逃逸、遮蔽的 builtin/工厂、过滤条件和模型
数据决定的序列拒绝。`kernel_only` 声明不能充当 Host 工厂选择的输入合同。
此项复用版本 32 的消费格式，局部 CPU/CUDA/Vulkan 无源码检查通过。GeoPhys 的 CUDA
检查使用原 Newton 工厂及其原生成式调用表达式，验证两个阶段独立选项；其最小宿主
使用明确有限声明，未证明原 Newton 的实例值 static choices、迭代计划和完整构造闭包。

## 模型决定的 CUDA 线程块

定义包版本 29 支持由已证明的模型整数表达式决定外层 CUDA range 的
`ti.loop_config(block_dim=...)`，例如 `ti.static(128 if self.dof > 32 else 32)`。
选择式使用既有 Host 参数表达式；prepare 从不可变参数快照一次确定 block、grid
和动态共享内存，原生 prepared 调用重放沿用这些结果。普通一次性调用在提交前绑定。
模型改变需要新的 prepared 调用，不修改其他实例或在途调用的启动描述符。

同一数值定义不按 DOF 生成副本。编译器保留启动上界，实际大小受加载函数和设备
容量约束；这不是模型尺寸额度。未知设备数据、可变 Graph 参数、嵌套/串行循环、
依赖固定 block 布局的 BLS/TLS reduction 不进入这条路径。普通固定 block 的 JIT
保持原机制，也没有新增自动调优或性能警告。原生 LLVM AOT schema 为 22，缓存为
102，旧构建产物须重建。

性能检查应分别覆盖首次准备、模型变更后的重新准备，以及正常 Host 调用的端到端
时间。`Graph.run(arguments)` 是每次重新绑定的便捷入口；尺寸和资源稳定时，在准备
阶段调用一次 `bind(...)` 并复用返回对象，才能摊薄绑定成本。预热后的 Graph 重放
计时不能替代首次准备和普通调用计时。

## 定义常量

版本 30 接入既有 `ResourceScope.constant('name')`，以及通过固定前端能力检查转发它的
普通 helper。常量必须来自不可变类属性，或构造器中无条件、单次的固定赋值；字面量、
模块常量和已证明的局部别名可作为来源。导出不执行构造器、getter、setter 或应用计算，
也不把模型参数、未知调用结果、条件赋值或重绑定冻结为常量。当前限定直接 owner 属性。

类继承按实际接收者解析常量覆盖。只有读取该常量的数值入口记录其值，常量不进入
消费者配置域，也不增加动态 ABI 参数；有限 `static` 配置仍沿原机制选择。声明时检查
固定值，普通调用和 Graph 重新 prepare 检查实际使用的常量，改变后须重建包。已经准备
的调用持有原快照，重放不重复读取常量或做配置选择。

CPU/CUDA/Vulkan 局部检查覆盖共享代码、继承覆盖、混合有限配置、实例状态、无源码消费
和 prepare 快照。GeoPhys 检查复用原 `declare_constant` 与布局 helper，以当前 EFC 的
固定 group size 值验证 DOF 17/129 使用一个入口；这不是整类 Newton 或全引擎资格。
原 Newton 后续仍受配置声明、迭代计划及构造闭包限制。此切片只改变 Python
Producer/Runtime 合同，不改变原生 AOT 格式，也没有新的整包体积或性能测量结果。

## 自由 Kernel 的 owner 参数

版本 50 支持具有一个 `ti.template()` owner 参数的模块级 Kernel，并支持从原调用
关系证明的额外不可变静态模板值。receiver 参数不要求叫
`self`，也不要求在第一个位置；来源从已声明类的普通 Host 方法、来源明确的子对象
路径及普通函数转发中证明。导出不调用这些方法来取得模型样本，不需要新增装饰器或
逐 Kernel 注册。只保存原定义中实际出现的参数元组，不展开各参数域的笛卡尔积。
当前静态来源为字面量、不可变 tuple 及普通函数转发；静态槽中的模型运行值、动态
工厂返回或无法确定的转发仍拒绝。早期格式 49 的自由 Kernel 包须重新导出。

数值定义交给原 Component 编译器，资源布局和实际静态依赖沿既有合同。多个已证明
receiver 类型可以引用同一份代码；实例选择单独存储，不按实例数量、尺寸或调用位置
复制数值代码。普通位置/关键字调用和 `GraphBuilder.dispatch(...,
template_args={'原参数名': owner})` 使用同一绑定，Graph 准备快照及写入资源查询继续
使用原机制，拒绝其他包的实例。来源不明的调用会在编译前与其他输入问题一起报告。

局部 CPU/CUDA 检查包含新尺寸、继承类型共用代码、独立实例、准备快照和无前端源码
的新进程消费。来源推导也跟随原 `GraphBuilder` / `create_sequential` 与普通函数转发，
识别明确的模板字典及由已证明 owner 类型过滤的字典；不执行 Graph 录制来发现入口。
会改变、逃逸或无法证明只读转发的字典拒绝作为来源，不把同名 `dispatch` 方法视为 Forge Graph。
GeoPhys 的三个 EFC 参数发布、Newton 条件与三个排序控制定义已通过这一输入预检查；
这不是完整 EFC 数值导出或整引擎资格。多模板检查另覆盖五个原调用元组共享三份必要
数值代码（访问器另计）、静态分支的未读值不增副本、动态输入和错误类型拒绝，以及
CUDA 无源码双实例消费。格式 51 将同一实际输入元组机制用于方法及继承的数值 mixin，
保留绑定方法和显式类调用语法；Graph 在准备时选择代码并绑定实例。CPU/CUDA 局部检查
覆盖保存的方法引用、独立实例、Graph receiver 不一致及未知运行时模板拒绝。
格式 52 还支持从同一 receiver 已声明路径取得的 Field 模板参数。直接调用与 Graph
复用原资源 ABI 和实例绑定，消费时按编译资源合同检查路径；未知路径、其他实例的字段
及未证明别名拒绝。局部 CPU/CUDA 检查覆盖新尺寸、继承 owner、独立实例和无源码 Graph
消费。无参数 Host 回调可沿用外层已证明输入，导出只检查回调体，不执行回调或 profiler；
带参回调、赋值表达式及重绑定捕获不能作为已证明模板来源。source/target 交换仍区别原
资源槽位 ABI，本切片未实现槽位归一化后的代码共享。
同一来源分析可追踪普通工厂返回的 Python 冻结 dataclass，包括嵌套记录与字面量
`getattr` 成员读取；导出不执行构造器或工厂。记录只转发已有 owner/资源来源及不可变
字面量，其实例不形成代码身份。可变或自定义记录构造、未证明的修改、不同返回来源
仍拒绝。CPU/CUDA 无源码检查覆盖这一转发及原资源 ABI；准备阶段从记录参数借用
字段仍须另外证明原分配来源。
嵌套局部调度、模型决定的方法查找、多 owner 输入及模型排序准备数据仍须继续处理；
尚无新的整引擎 wheel 或体积测量。

格式 53 在普通准备方法中发现显式资源组上下文，不限于构造器；导出不调用这些方法，
也不新增注册装饰器。保留的 Host 方法决定分配时机，同一上下文再次执行时创建新实例组，
已准备调用继续持有原资源租约。原生成器负责 finalization；上下文失败会释放新组并恢复
原字段绑定，但不回滚上下文外的任意 Host 修改。局部 CPU/CUDA 检查覆盖 prepare 前无分配、
新尺寸、独立实例、旧 Graph 调用及无源码消费。延迟 raw/default-root 分配及
条件方法参数暂不在此切片内；同实例同资源组的递归或并发准备拒绝。

普通准备 helper 也可用 `scope.child = Child(owner)` 创建声明的子对象，输入须有可证明的
owner 来源。先传播构造期已知输入，再补入准备函数的子对象声明，最后做完整输入准入；
导出不执行准备函数。子对象复用已有 managed construction 和分配失败释放机制，父对象
不必在 `__init__` 提前分配它；Host 缓存守卫可保持重复调用时的对象身份。CPU/CUDA 局部
检查覆盖父引用、不同尺寸、子构造失败无泄漏、Graph、独立释放和禁止 producer 源码的
新进程消费。这不使任意 Host 修改具有事务性，也不放宽未知构造输入的准入。
准备 helper 可使用另一个来源明确的 helper 对同一 owner 声明的布尔域；Field 投影复用
具体 owner 的完整合同，不由源码模块遍历顺序决定条件分配是否通过。条件仍须具有声明域，
不执行任一 helper 来发现它。

格式 54 保留 `scope.record(..., optional=True)` 声明的可选普通记录。
在已证明的 `is not None` 分支中声明成员，复用原记录存在性合同；只有实际读取该
记录的 Kernel 选择必要的存在/缺失实现，记录内尺寸和值仍是运行数据，未使用记录和
选项不扩大代码域。CPU/CUDA 局部检查覆盖构造与后续准备、存在性切换、独立实例、
已准备调用、约束及无源码消费。准备方法可以使用只声明元数据的 scope，实际 Field
分配仍须有显式资源组上下文。本切片尚未解决任意外部绑定记录、条件子对象分配或
来源未证明的借用 Field。

格式 55 支持记录成员借用同一 owner 内已由定义证明的分配路径，包括后续准备方法。
ABI 来自原分配声明，记录成员必须已指向该字段；冻结记录只核对、不改写。源与目标
维度关系继续验证，重新绑定后已准备 Graph 调用保留原资源。CPU/CUDA 无源码局部检查
拒绝跨实例记录成员、维度不符和后续别名替换。不从任意记录参数猜测布局，也不执行
绑定工厂取得模型样本。

格式 56 将同一借用机制用于已证明原分配来源的准备参数。已有 Host 调用分析追踪冻结
记录工厂、普通方法转发及前置的单次 owner 属性赋值；已发现的调用必须收敛到一个
源 owner 类型和 Field 成员，未知或冲突来源在数值编译前拒绝。准备时绑定调用者的
实际实例，不复制或重新分配源资源。消费端检查包、类型、路径、别名和维度关系后
才更新私有来源引用；失败不替换该引用，但不回滚此前的任意 Host 写入。CPU/CUDA
无源码检查覆盖新尺寸、独立/重新绑定的输入和旧 Graph 快照。

准备声明也可借用在另一普通绑定方法中赋值的 `self` 字段：只接受一个直接赋值来源，
并沿该方法的每个已知调用证明原分配类型；构造器的初始 `None` 不算另一分配来源。
借用声明处仍检查实际 Field、原分配成员和所属实例，随后更新私有来源；单独改写 Host
字段不会刷新已有绑定。此规则不推断方法执行顺序，多写入方法、条件赋值和未知参数
转发仍拒绝。局部 CPU/CUDA 无源码检查包括新尺寸、错误来源、重绑定和旧 Graph 快照。

格式 57 同时支持这些工厂提供的可选 Field 成员。仅声明元数据的非 None 分支或已证明
的可选声明辅助函数复用原条件 Field 合同；准备时更新存在性，缺失时清除旧私有来源。
维度表达式仍只在存在分支求值。只有实际读取成员的入口保留存在性特化，另一个未用
可选输入不使其代码倍增。局部 CPU/CUDA 及无源码检查覆盖存在/缺失/重新绑定、条件
源分配及旧 Graph 快照；未知来源和没有存在性保护的数值读取拒绝。任意可选表达式、
晚期子 owner 构造和更复杂绑定工厂仍须另行处理。
同一个非 None 分支也可声明以该借用为 `when` 的 `require_le` 约束；显式容量约束与
自动生成的源/目标维度关系合并保留。缺失分支不求值这些约束；后续使用或准备新调用
仍检查它们，不因 Host 已执行过声明而省略。无关资源的约束不能借此 guard 放行。

准备声明可遍历固定、互异的字段名 tuple/list，调用原借用 helper 或在成员非 None
分支内声明借用及约束；记录作用域使用同一规则。未遮蔽的 `getattr(binding, name)`
按字面量成员路径读取，不运行工厂，也不展开模型数据或数值循环。跨记录的借用维度
关系须使用原 `record.parent_dim`，直接混用另一作用域的 Dimension 仍拒绝。
局部 CPU/CUDA 无源码检查覆盖此声明形式；这不补全任意跨方法的字段绑定来源。
普通声明 helper 也可组合上述借用操作，含固定成员名循环、未遮蔽的字面量 `getattr`
和已证明的可选借用 helper。沿用原 helper 输入单次求值、词法别名及来源摘要；
动态成员表、遮蔽的 `getattr` 和带默认值的成员查找仍拒绝，不执行 helper 来发现布局。

格式 58 允许已声明可选记录的存在分支拥有显式工作区组，直接复用记录存在性，不增加
一份配置布尔量。未使用该记录的入口不增加代码；记录缺失时不求值成员尺寸，也不分配
对应工作区。借用该工作区仍检查源记录的存在性，不能沿已失效的来源发起新调用。
同一普通准备方法中的多个显式组一起换代，避免旧组尺寸阻止新模型准备；原 Host
提前返回且未进入分配上下文时不改变资源。失败释放本次新分配并恢复原字段绑定；
上下文之外的任意 Host 写入不在回滚范围。已有 Graph 保留旧资源租约，新的实例和
调用绑定相互独立。局部 CPU/CUDA 无源码检查覆盖这些行为，不代表完整引擎已导出。

普通 Graph 转发可用未遮蔽的 `isinstance` 过滤已证明分配来源的 Field。仅当所有可能的
Field 类型（可选输入还包含 None）得到相同结果时，来源分析才采用该判断；不执行自定义
类型检查，也不猜测尚未确定的 Field 子类型。Host 包装对象过滤后仍保留原字段路径，
不因此增加代码版本。局部 CPU/CUDA 无源码检查覆盖转发、独立实例，以及自定义、遮蔽
和歧义类型判断的拒绝。

工作区声明可以读取另一已声明 Field 的 `.dtype`，包含同实例别名和张量的标量类型。
解析依据资源合同，不运行构造样例；未知来源或循环类型依赖明确拒绝。

版本 62 按实际 Python 方法继承关系收集准备声明，包含没有构造函数的普通 mixin。
类型化输入、数值和显式工作区组绑定到具体实例的合同，mixin 不产生另一份发行根。
局部 CPU/CUDA 检查覆盖跨文件输入、独立实例、延迟工作区换代、失败释放和旧 Graph
代际保留；歧义组身份和自定义实例查找拒绝。这不代表完整 EFC 导出已通过。

模型维度约束继续保留在真实输入准入中。定义导出的临时类型/布局样例不必满足某个
实际模型的不等式，但声明引用和约束结构仍在导出时检查；普通 Component 捕获仍检查
真实模型。局部 CPU/CUDA 检查覆盖 `count >= n + 2` 的合法输入及过小输入拒绝，
避免将统一为 1 的临时尺寸误当成模型不合法。

可选记录仍可能是某个已到达数值分支的必需输入。导出只排除捕获器明确诊断为缺少该
记录的选择，并继续探索该分支新读到的依赖；其他编译错误仍终止导出。消费者在提交前
拒绝缺少输入的选择。例如驱动启用时可以要求质量数据，而无需把它声明成所有入口的
必需输入，也不会静默跳过驱动计算。

动态输入存在性与固定后端布尔条件组合时（例如 `ti.static(packet is not None and
ti.lang.impl.current_cfg().arch == ti.cuda)`），准入保留完整条件来源；没有到达的分支
不要求该输入。另一输入在已到达分支中被读取时仍必须提供。该处理复用同一份代码，
不通过放松检查或枚举输入有无来绕过准入。

同一准入规则也适用于由已声明配置控制的条件 Field：直接使用专用工作区的入口只为
工作区存在的配置生成代码；消费者在缺少工作区时拒绝调用。探索仍以该入口实际读取
的依赖为依据，无关配置不展开成代码副本；若没有任何可调用配置则明确报错。

普通自由 Host 函数也可为正常调用源码证明的 owner 准备显式独立资源组，复用既有
组合同、替换事务和调用租约；导出不执行该函数或样本模型。函数及失败处理仍保留为
Python。多个接收类可复用同一声明；准备 receiver 被重新绑定或声明合同不相容时拒绝。
普通 Host 包装函数可将未改写的输入参数直接转发到已有来源证明的资源组准备入口。
这不增加接收类型或代码变体；原准备事务在函数体执行前验证加载 owner 的合同。
未知工厂、被改写的转发参数和没有该分配边界的纯值准备函数仍不在此支持范围。
定义分析也识别函数内部从已有源码闭包导入的准备函数及模块别名，不执行 Host 函数。
局部 import 若覆盖 owner 参数，不得沿用覆盖前的 owner 来源。
普通 Host 转发含运行时 `**mapping` 或尾部未知 `*sequence` 时，仍保留已证明的显式参数。
这些选项不提供声明事实或增加代码变体；未知位置展开之后的参数不能据其位置证明来源。
直接 Kernel 的模板输入仍要求显式且已证明的绑定。
此支持尚不包括准备时将同一资源属性切换为不相容元素类型。
准备函数可引用 owner 已声明的布尔域，包括后端资格限定的单个布尔取值；控制资源
布局的标志不能声明为 `kernel_only`。不同类型资源继续使用原条件组布局及旧调用租约。
反向依赖也使用这一合同：外部准备函数的无条件 static 声明可供父构造中的资源条件读取。
导出先从已证明的调用接收者收集声明域，再完整校验构造和准备函数；预收集不执行 Host，
不改变调用顺序，也不跳过资源使用校验。CPU/CUDA 局部检查覆盖新尺寸、两实例及独立进程消费。
只声明 value/static 而不分配资源的准备函数也沿用此路径：正常 Host 计算保留为 Python，
声明通过实际 ResourceScope 或已证明的 scope factory 以及共用声明 helper 解析。
不从样本模型的角色列表提取合同；声明 scope 逃逸与布局条件错误仍由完整准入拒绝。
共用声明 helper 中的 `static_dtype` 复用已有标量类型身份：实际读取该类型的数值入口
保留必要特化，未读入口不复制。单一存储 dtype 可用于 Field 类型；不同 dtype 改变
Field ABI 的选择仍拒绝。导出不执行类型工厂，消费 Host 使用类型名称，无须导入数值源码。
CPU/CUDA 局部检查覆盖数值类型选择、固定存储类型、独立实例及独立进程无源码消费。
声明 helper 可保留由已声明布尔域控制的 `if`/`else`，包括取反条件；两分支的资源角色
仍受原条件约束。分支内部局部名称不向外泄漏，也不能覆盖已有 helper 局部绑定。
未声明条件、`kernel_only` 资源条件及条件内返回/continue 拒绝，不能用样本值裁掉分支。
准备函数的静态枚举域可以引用 owner 已声明的定义常量。预检先以原常量规则解析父对象
的固定声明，再检查准备域；完整构造/资源准入仍执行。类常量和无条件固定赋值均可，
未声明常量、模型赋值及描述符拒绝，不读取样本实例，也不执行准备函数来获得取值。
准备函数的顶层 `if not self.enabled: return` 可沿已有布尔域控制余下资源；导出保留
原条件与 Host 返回语义，同条件下的 `borrow(..., source_scope=True)` 复用原分配。
未声明条件、跨出分配条件的别名及其他未证明的提前返回拒绝，不把余下资源当成无条件资源。

动态局部向量/矩阵也可用于 `range(begin, ti.min(device_count, model_bound))`。
`begin` 和 `model_bound` 必须来自可证明的整数维度/常量表达式；prepare 按上界分配
调用工作区，设备仍按实际计数执行，不读取设备计数准备空间，也不扩大实际 Launch。
该上界不是精确维度或静态条件证明，不跨可能溢出的算术传播；无界设备范围仍拒绝。

## 启动时选择 JIT 与 AOT 混合执行

需要脚本 JIT 和多个已封装计算库共同工作时，在正常初始化中选择一次混合模式：

```python
import taichi_forge as ti

ti.init(arch=ti.cuda, execution_mode="hybrid")
from example_app import main  # 该脚本内部照常 import 各计算模块
main()
ti.reset()
```

也可设置 `FORGE_EXECUTION_MODE=hybrid` 并沿用普通 `ti.init(arch=...)`。
未设置时保持 JIT；显式 `execution_mode="jit"` 可覆盖环境设置。无需逐模块选择路径，
无需把整个示例包在 `ExecutionSession` 上下文中。已发现的定义包及依赖按原模块名加载，
其他脚本（包括同一父包中的未封装脚本）正常导入并可运行 JIT Kernel。已声明的数值模块
遇到错误后端、歧义或损坏产物时仍拒绝；不能借混合模式回退编译该模块的私有源码。

AOT 库自动借用当前 JIT Program；不另建计算设备。传入标量/固定张量的 JIT ndarray、
合格 Dense Field 或 `ndarray_view` 时，在原参数/资源准备边界自动建立并缓存借用视图。
调用方保留原对象；dtype、元素形状、模型尺寸、布局和存活期继续验证，输出写回同一存储。
原始 Field 不必成为库的分配闭包。已准备 Graph 保留独立绑定和租约，重放不重复导入；
不为连接脚本和核心增加逐阶段全局等待，也不生成组合 TCM。

模式须在导入核心计算模块前选择，可统一放入启动文件；已导入/实例化的源码对象不会被
原地换成 AOT。`ti.reset()` 按现有生命周期关闭包和借用 Runtime，随后清理本次创建的
公共数值模块名；普通脚本模块不删除，其持有的旧计算对象随 reset 失效。
独立执行域、复杂未资格布局及任意对象协议不因本开关自动获得支持。

局部 CPU/CUDA 验证覆盖同一脚本调用两份独立库、JIT 输入准备及后处理、直接与 Graph
调用、不同尺寸/交错 Field/ndarray、错误绑定及树退休。EFC CUDA 检查直接传 JIT Field，
12 组结果与原 JIT 参考一致。冷启动与缓存后首调必须分别测量，不能仅凭首次加载更快
宣称运行性能更好。

普通 `owner.method(...)` 自动在实例上复用未变化的原生 PreparedCall、参数帧和局部 workspace，
不需要用户增加 `prepare()`。首调及相关配置、输入资源或参数变化时执行原准入/绑定；
同一绑定首次复用时才建立原生 PreparedCall，单次调用和持续变化的标量不反复准备原生图。
准备阶段直接使用 JIT/AOT 数组的权威视图，将参数帧、资源引用、线程块大小和共享内存大小
交给既有原生执行机制固定。稳定热调用只比较相关 Host 输入并沿原租约提交，不重新解析
准入合同、编码数组描述符或重建原生启动上下文。改变绑定时退休旧调用会等待在途工作；
不缓存历史参数组合。准备不重新编译数值定义，也不把模型尺寸变成新的发行代码副本。
设备内容始终实时读取，实例之间不共享可变状态。显式 Host 数组仍每次上传/回写，
可变张量参数仍获取新的值快照；不能缓存它们的结果或省略这些必要传输。
CPU/CUDA 开发断言轮询由显式 debug 模式启用，发行模式的同步和传输不插入错误查询。

CUDA bitcode 的低层 `BoundCall.prepare(specialize=True, constant_args=(...))`
提供实验性的准备期后端特化。它使用已绑定 ndarray 的形状/步长，以及显式指定的整数
标量参数下标，折叠包内 LLVM IR 的对应 ABI 读取，再复用既有 CUDA 后端编译。
同一分配上的字段/视图还会使用已绑定的存储身份恢复共同基址及相对字节偏移；
代码缓存只记录参数槽位和相对关系，不记录分配身份或设备地址。正负偏移和重叠视图
保持原语义，独立分配或无法证明关系的输入保留原寻址，不假定全部数组互不重叠。
设备地址、数组内容、其他标量仍由各 prepared 实例绑定；新尺寸/指定标量需要新准备。
回调只在能证明继承同一 RuntimeContext 时参与，`real_func` 自建参数上下文不混用。
这不需要原数值 Python 源码，也不改变发行 TCM 或枚举模型组合。

此选项目前用于单 Kernel 的局部试验，普通 package 调用和 Graph prepare 默认不启用。
相容代码在加载模块内复用，实例/在途生命周期沿用已有机制。普通入口查找仍可能先
编译通用代码；首次特化是额外成本。同模块命中不再编译，但跨进程仅复用已有 CUDA
后端/驱动缓存，仍要执行 LLVM 优化，并无完整特化磁盘缓存。应同时记录首次准备、
缓存后准备、稳定调用耗时和实际本地代码占用，再决定是否启用；不能只看热核时间。
特化代码缓存与原生调用准备复用承担不同职责。前者保存相容目标代码，后者保存实例的
参数帧/资源绑定和提交状态；特化直接接入同一个 prepare，不引入第二套实例准备流程。
特化成功并不意味着普通入口的参数上传和启动开销已经消失。

## 独立 AOT Runtime 的普通导入

无需脚本 JIT 的独立部署也可以在首次导入引擎前，通过 Forge Runtime 选择执行模式。JIT/AOT 使用同一份
业务导入、构造和调用代码；不需要 `load_package`、TCM 文件名或 `session.module`：

```python
from taichi_forge_runtime import ExecutionSession

with ExecutionSession(mode="aot", arch="cuda"):
    from constraints.efc.solver import TiConstraintSolver

    solver = TiConstraintSolver(max_nefc=128, nv=19, enabled_methods=("newton",))
    # 正常准备输入、bind_solver_fields / load_constraints
    # solver.solve(method="newton", iterations=60, tolerance=1e-6)
    # solver.back_project()
```

改成 `mode="jit"` 后，正常导入源码并沿原 JIT 执行。省略 `mode` 时读取
`FORGE_EXECUTION_MODE`，缺省为 `jit`；可以将上述启动代码放在应用唯一入口，
让业务文件继续使用普通 `import`。输入对象仍须满足各路径原有合同；这不是任意
Python/Field 对象都可无转换跨 Runtime 传递的承诺。

AOT 启动只读取索引，首次业务导入才加载对应数值包。查找来源是已安装 distribution
的文件记录中的 `package.json`、`sys.path` 各目录本身的 `package.json` 或其下的
`forge_aot/**/package.json`，
以及 `package_paths` / `FORGE_AOT_PACKAGE_PATH` 指定目录中的清单。无需新增装饰器、
逐 Kernel 注册或 provider 工厂。现有 ZIP 须先解压；例如本地切片可以设置
`package_paths=["D:/sdk/efc-cuda"]`，正式安装的 SDK 则无需这个路径参数。

选择按普通模块名和目标后端进行：该模块的正式导出根优先于其他包的依赖投影，
同根同后端多份候选明确报歧义；不按目录顺序猜测。已接管的应用命名空间缺少模块、
后端不符、载荷损坏或不相容时拒绝，不回退私有 JIT。无关 Python 脚本/依赖照常导入。
共享父命名空间可容纳独立数值库，不因此产生仿真+渲染组合根。

模块和包均按 session 缓存；求解调用没有新增检索、代理解释器或逐核调度。原生
Runtime 的 prepare/执行、实例绑定和退休语义继续复用。关闭 session 会移除它创建的
公共导入名并释放其包/自有 Runtime；不能在已导入源码对象上原地切换模式，也不能
同时激活两套进程级 AOT 导入规则。先于引擎 import 初始化；应用线程退出、调用释放后
再关闭 session。传入 `runtime=existing_runtime` 可复用调用方设备，其所有权不转移。
JIT 模式复用同后端的既有 Runtime；新建时可用 `jit_options`，自建 Runtime 随 session 关闭。

当前局部 CPU/CUDA 检查覆盖普通 import、源码 JIT、无前端 AOT、安装记录/导入路径发现、
模块缓存、实例隔离、缺包/后端/歧义拒绝和关闭。GeoPhys 冻结 EFC 包通过普通 import 的
12 组 PGS/CG/Newton 与原 JIT 对照；这不代表整引擎所有公开包已完成导出。

## 仍需补齐的共同机制

格式 71 将正常 `ResourceScope.ndarray(dtype, shape=..., initialization=...)`
接入包导出，复用原独立 ndarray ABI，不将数组放入 SNode 组。尺寸来自声明的
`dim/derived_dim` 及其代数，实例可使用新尺寸和空数组；条件分配沿用已声明布尔守卫。
CPU/CUDA/Vulkan 局部检查覆盖构造器和准备 helper、标量/向量数组、普通 JIT 对照、
无源码双实例消费及构造失败释放。初始化只发生在分配时；LLVM 复用分配器清零，
Vulkan 的显式 `zero` 策略暂用一次 Host 零字节上传。未测量其大数组准备成本。
该检查不表示 SAP/provider 或完整刚体闭包已合格；模型选择的元素类型仍需独立准入。

Field 的 dtype 也可通过同一 ResourceScope 读取既有 `static_dtype` 声明，
包括另一准备 helper 已声明的单一存储类型；沿用原 owner 类型与有限域检查。
不同准备函数可重复声明完全一致的静态域；每处 Host 声明仍保留位置和调用行为，
owner 只有一份合同。不同 choices、`kernel_only` 或条件/路径不兼容仍拒绝。
自由准备函数复用构造器已有的后端分支选择：先按选定目标裁剪分配分支，再发现
资源工厂和合同；Host 投影保留原目标守卫。CPU/CUDA 局部检查覆盖不同类型/秩的
后端分配与新实例尺寸，不把另一个后端的布局混入当前包。
这不会从实例推断 dtype，也不增加类型组合。
正常 Host 准备可通过 scope 的属性或未被替换的 `getattr(scope, '名称', 默认值)`
读取已声明、无条件的标量角色。该放行只针对声明值；Scope 本身逃逸、未知属性和
动态名称仍拒绝，Host 策略不进入数值代码身份。
无 `else` 的资源分配条件可使用已声明布尔角色的 `A and not B`，按嵌套资源守卫
处理，保留 Host 短路语义；只有读取这些资源的入口受影响。任意模型比较、`or`
或含替代分配的复合条件尚不在此局部支持范围内。

格式 70 支持独立默认 AOS Field 的有限形状选择，例如
`shape = (n,) if self.packed else (n, width)`。条件须为已有的非 `kernel_only`
布尔静态声明；每个分支的尺寸沿用已声明模型维度及其代数。只有实际读取此布局的
数值入口保留必要变体，无关入口共享一份代码，模型尺寸仍在实例准备时确定。
CPU/CUDA 局部检查覆盖嵌套 owner、非拥有输入、普通 JIT 对照及无源码双实例消费。
原生 SNode 编译器仍负责实际字节布局。该支持暂不包含显式 placement/order、
StructField 或跨形状选择的 `field_like` 克隆；这些情况明确拒绝。

复杂 SNode/Field 布局、上述继承限制、模板参数域/其余条件资源域、无类型或 Python 专用 `pyfunc`、梯度、任意 Python
资源工厂、完整 Host 数组访问接口、完整 Graph/ExecutionPlan 和 provider 引用还没有接入。
当前识别到不支持的声明或 Host 前端操作会拒绝导出，不借助样本运行或私有 JIT 回退。
这不等于已完成对任意 Python Host 代码的语义验证。

`func` 仍使用既有的内联编译机制；一个 TCM 中有多个入口，并不证明不同 Kernel
内的 helper 或静态特化已完全去重。该原型没有建立组合发行根，也没有新增静态组合
枚举器；它验证的是通用发现、编译入口和 Host 投影。全引擎共享代码、合法静态域及
最终同范围 wheel 体积仍需单独验收，不能由这个微型包的体积推算。
