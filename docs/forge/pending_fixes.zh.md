# 待发布修复

[English](pending_fixes.en.md) · [发布说明](release_notes.zh.md) · [文档入口](index.zh.md)

本页记录**源码已修复、发行包尚未包含**的问题。当前公开版本为 **0.7.0**；
升级到同版本或重新安装不会获得下列修复。下一版本号确定后更新发布版本栏。

## 已修复，待发布

| 编号 | 受影响版本 | 症状与修复 | 修复发布版本 |
| --- | --- | --- | --- |
| F070-1 | 0.7.0 | `@ti.data_oriented` 类中的 `@ti.kernel(opt_level=...)` 方法可能在导入时要求给 `self` 添加类型标注。已修正参数化装饰器的类方法识别；保留裸 `@ti.kernel` 和模板 owner 绑定。 | 下一版本，待定 |
| F070-2 | 0.7.0 | Graph 配置候选漏掉 Sequential、WHILE 条件/循环体；同一 kernel 的 `A → B → A` 调用可能使 `recipe_catalog()` 报“不连续区域”错误。已支持原位配置每处 dispatch，并递归处理冻结的结构化区域，保留顺序、绑定、停止条件和 baseline。 | 下一版本，待定 |
| F070-3 | 0.7.0 | CPU `fast` 强制 LLVM O0，仿真循环保留反复执行的地址和聚合对象操作。已通过统一模块配置改为 O1，并单独更新缓存 schema。冷编译可能增加，个别工作负载可能回退。 | 下一版本，待定 |
| F070-4 | 0.7.0 | 关闭高级 IR 优化时，嵌套反向循环可能把冗余局部控制状态变成昂贵的 AD 栈操作。已在生成伴随前清理局部数据流，遵守 `cfg_optimization` 和 `fast_math`，并使旧产物失效。 | 下一版本，待定 |
| F070-5 | 0.7.0 | 零维矩阵字段整体赋值可能为每个分量保留一个写入内核。CPU/CUDA 在 AD 记录之外，对独立同质 f32/f64 Matrix 值复用批量传输，保留主机舍入和回退语义。Vulkan 因批量路径实测增加主机内存，继续使用标量赋值。 | 下一版本，待定 |
| F070-6 | 0.7.0 | Vulkan 嵌套反向 kernel 中重复的条件字段读取可能生成冗余梯度原子更新。已在求导前执行一批有上限的高级简化，保留 AD 内存保护、配置开关和后续 lowering，并使旧缓存产物失效。 | 下一版本，待定 |

F070-2 的配置候选适用于 CUDA/Vulkan primal kernel；CPU 保留原有执行路径，
梯度 kernel 不作为本轮配置候选。候选只在物化时编译，重放不增加搜索或配置转换。
物化报告新增结构化区域的已编译 task 记录，用于核对实际配置；它不是逐轮执行轨迹。

修复提交与小型回归：

- F070-1：`0e7181148`；CPU/CUDA/Vulkan 装饰器、owner 绑定与 Graph 调用。
- F070-2：`47bd01d1d`、`f921d6217`；交错调用、重复 Sequential、WHILE 零轮/提前结束/预算耗尽、嵌套分支、retry、AOT 前向与反向。
- F070-3：`e50ec7014`；CPU 聚合对象访存消除、克隆/缓存中的模块配置，以及 CPU AD、原子和缓存回归。显式 `balanced` 配合 `llvm_opt_level=0` 仍可使用；GPU 优化等级保持不变。
- F070-4：`65ca7840c`；带分支、空循环和相邻输入的嵌套递推解析梯度，以及 CFG、AD、缓存和 AOT 检查。CUDA Wave AD 从此局部状态清理获益，Vulkan 另由下方 F070-6 准备步骤处理；F070-4 不启用全局内存转发或完整高级优化。
- F070-5：`be6680f24`；编译产物数量、大整数到 f32 的双重舍入、f64/特殊值、别名、Tape 与 Vulkan 回退。独立 LBM 对照覆盖 CPU/CUDA/Vulkan；内存与编译收益限定于 CPU/CUDA，不声称 CUDA 稳态吞吐提高。
- F070-6：`ef5c90d14`；CPU/CUDA/Vulkan 独立转置模板梯度，覆盖边界读取、邻居贡献、变化/空循环以及 CFG/fast-math 开关；另有现有 AD、CFG、缓存与 AOT 回归。六对无 profiler 的 Vulkan Wave AD 实测改善 1.40 倍，原严格字段检查通过。primal 与非嵌套路径保持原档位，不代表所有 Vulkan 工作负载普遍加速。

F070-3 至 F070-6 描述源码改动，不代表已发布 0.7.0 wheel 的行为。范围与诊断开关见
[编译权衡](compilation_tradeoffs.zh.md)。这些改动均不保证所有工作负载加速或跨后端逐位一致。

## 随版本维护

- 新问题使用固定编号，写清已知受影响版本、症状、修复提交和修复发布版本；不推断未核查的旧版本。
- 准备新版本时，核对发布源码确实包含修复，并填写计划发布版本；发布完成前仍留在“待发布”。
- GitHub Release 与对应发行包发布后，将条目移到下方“已发布修复”，填写实际版本并链接发行说明；中英文同步更新。
- 若修复撤回或仍不完整，应立即修正状态与范围。此页不代替未修复问题的 issue 跟踪。
